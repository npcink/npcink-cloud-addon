# Addon 正式 monitoring 开发复盘（2026-08-19）

## 结果

本阶段将 monitoring 授权从“管理员自行寻找设置页”改为“连接验证完成后的明确确认框”，
并构建了可人工安装的候选 ZIP。没有调用真实 Provider，没有发布 WordPress.org，也没有部署正式站点。

## 经验规范

1. 把连接、验证、同意和传输拆成独立事实；不要用一个设置开关代替整个流程。
2. 授权动作必须靠近管理员刚刚完成的连接验证，降低遗漏和支持成本。
3. 拒绝路径必须与允许路径一样有测试，且拒绝不能产生隐式 Cloud 请求。
4. 复用现有权限处理和 nonce/capability 检查，避免新增并行写路径。
5. 构建包后必须检查精确 ZIP、manifest、Plugin Check 和干净 Playground 激活，而不是只看源码测试。
6. 交付状态要明确区分：代码验证、候选包、合并、正式发布、生产安装。

## 自我检查

- 已验证：确认框显示、允许/拒绝行为、无额外 Cloud HTTP、包内容完整、默认 fail-closed。
- 未完成：真实站点人工安装后的浏览器观察，属于下一步人工验收，不在本次自动执行。
- 主要纠偏：不再把 cohort 解释成正式用户批次，也不要求正式用户承担测试操作。

## 人工安装后检查

1. 备份当前站点和 Addon 目录/版本信息；
2. 上传并安装 `build/npcink-cloud-addon.zip`；
3. 完成连接验证，确认一次性 consent dialog 出现；
4. 分别观察允许和暂不允许路径；
5. 检查 monitoring 状态、站点运行不受影响；
6. 如需回滚，恢复上一版本 ZIP，不修改 Cloud 生产数据。
