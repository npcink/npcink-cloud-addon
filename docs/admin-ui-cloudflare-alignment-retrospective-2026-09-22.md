# Cloud Addon 管理界面对齐 Cloudflare 设计语言复盘

状态：Accepted（2026-09-22）

适用范围：`npcink-cloud-addon` 三个设置页标签（概览、站点知识库、高级与排查）
的展示层改造，以及由此沉淀的跨项目设计规范。本文记录这一轮做了什么、踩过
什么坑、哪些方法可直接复用。设计规则本身以
`npcink-workflow-toolbox/docs/admin-ui-design-standard-v1.md` 为准；本文不
重复设计规则，只记录落地经验。

## 1. 背景与交付清单

用户反馈界面"不合理也不科学"，期望对齐 dash.cloudflare.com 后台的观感。
经过对 CF 账户首页、域名概览、SSL/TLS 设置页的实际走查，结论是差距不在配
色而在两件事：**同一事实的重复表达密度**和**组件层级**。由此先沉淀跨项目
规范，再逐标签页落地。

## 2. 设计层面的核心结论

1. **一个事实只说一遍**：数字、百分比、图形条是同一事实的三种表达，只保
   留两种（大数字 + 4px 连续进度条），百分比放进 `aria-valuenow` 和悬停提
   示。"剩余 96%"这类可见文字列全部删除。
2. **需要截断的列表等于不该出现的列表**：站点知识库 782 条截断 50 条的表
   格被整体移除，本地只留计数和 Cloud 链接。判断标准：该信息是否改变用户
   在 WordPress 里的下一步。
3. **折叠把控件藏起来时，summary 是唯一状态信号**：折叠组 summary 携带状
   态后缀（`隐私设置 · 匿名诊断已关闭`）；与此相对，开关可见时再写"已启
   用"才是冗余。两者不矛盾，区别在控件是否可见。
4. **重复的解释合并成一行**：高级排查三条相同的能力过期说明合并为表格内
   一行共享说明（colspan），行内只留徽章。
5. **层级克制**：每屏一个实心主按钮；卡片标题 16px；标题与第一行内容之间
   靠行距不靠分隔线。

## 3. 可复用的工程经验

### 3.1 契约先行，改呈现必须同步契约

本轮每个 PR 都伴随 `tests/static-contracts.php` 或
`tests/behavior-settings-page-contract.php` 的同步更新。原则是**保意图、
换实现**：契约锁定的是" compact 配额行存在""不复制 Cloud 明细"这类意图，
锁到实现细节的子句（如 `repeating-linear-gradient`、具体 grid 模板列宽、
旧 consent 类名）随实现更新。反面教训是这些契约曾把分段渐变、四列网格等
实现细节钉死，导致后续每次视觉迭代都要先解钉。新增契约时建议只钉：关键
字符串的存在/不存在、数据属性、函数存在性，不钉具体 CSS 值。

### 3.2 跨仓库类名冲突是真实风险

`npcink-governance-core` 与本仓库都定义了无前缀的 `.npcink-ai-tabs`，而两
者同挂 `npcink-ai` 菜单，存在同页覆盖风险。规范已把治理仓库改名列为前置
项。同时注意：**复用任何历史组件类名前先查静态契约**——
`.npcink-cloud-inline-info` 和 `.npcink-cloud-capability-popover` 是被特
意删除并明令禁止复用的类名，本轮的 ⓘ 提示因此用了新的
`npcink-cloud-info-hint`。

### 3.3 i18n 三件套与回退映射必须原子化同步

文案改动的完整链条：`i18n:pot` → `i18n:update-po` → 手工填写 zh_CN 翻译 →
`i18n:update-po` 后如无遗漏则 `i18n:make-mo` → `i18n:check`。两个坑：

- **po 重复 msgid 会让 make-mo 出错**。`Ready` 这类短词可能已存在于 po（来
  自其他源码位置），新字符串入源后先 grep po 再补翻译，不要盲加条目。
- **回退映射键必须与源码字符串逐字一致**。改一句文案 = 源字符串 + 回退映
  射键 + po 三处同改；废弃源字符串后记得删映射条目（如本轮的
  `%d%% remaining`、`Pending content (%d)`），否则留下永远命不中的死键。

### 3.4 用测试桩渲染真实 HTML 做视觉验证

不登录线上后台也能拿到真实标记：复用 `tests/helpers.php` 桩环境和
`behavior-settings-page-contract.php` 开头的 stub 段（12–145 行），seed 种
子数据后反射调用渲染器，把输出包进真 `admin.css` + 站点 `wp-admin/css/`
基础样式，`php -S` 起本地服务后截图。三个注意点：

- `filter_input(INPUT_GET, ...)` 在 CLI 桩环境读不到运行时写入的 `$_GET`，
  渲染非默认标签页要用反射直接调用对应渲染函数，而不是设 `$_GET`。
- fixture 尽量贴近生产数据（真实的额度数值、中文环境的字符串长度），英文
  stub 渲染只验布局不验文案。
- 每个 PR 至少验证 1440px 与 480px 两档；宽屏暴露对齐问题，窄屏暴露堆叠
  问题。

### 3.5 CSS 实现取舍的具体教训

- **统计列分隔线用每格 `border-left`，不用容器底色 + gap**：后者在统计格
  被隐藏时（如额度暂不可用）会留下灰色空洞；前者最坏情况是隐藏格后面的可
  见格多一条边线。
- **`format_empty` 会把空字符串填成 "unavailable"**：给刻意留空的去重单元
  格带来杂音，render 层直接输出原值即可。
- **去重条件是 `unique 数 === 1`**：判断"全部相同"时写反成 `count === unique`
  不会报错，只会静默不生效——靠预览截图才暴露。
- 带专属类的元素要配套 `[hidden]` 规则：`display:flex/grid` 会覆盖
  `hidden` 属性的默认行为。

### 3.6 交付流程

- `composer pr:publish` 遇到 github.com 443 超时（api.github.com 可能同
  时可达）属间歇性网络问题，等待 60–90 秒重试即可，不要绕道改推送通道；
  本会话两次发布均重试成功。
- squash 合并后 `git pull --ff-only` 同步本地 master，再从新基线开下一个
  分支，避免下个分支基线落后。
- 纯展示层改动 `smoke:playground` 不适用，但必须在 PR 验证记录里写明理由。

## 4. 边界与克制（本轮自检通过项）

- 渲染保持零 Cloud HTTP；所有额度/用量仍来自既有只读缓存投影。
- 未新增任何本地控制面：没有刷新按钮常驻、没有索引明细、没有运行记录。
- Cloud 拥有额度、索引、运行真相；本地只重排既有投影的呈现。
- 行为合同覆盖的健康态隐藏恢复按钮、失败态单一恢复入口、顶层入口数量等
  断言全部保持。
